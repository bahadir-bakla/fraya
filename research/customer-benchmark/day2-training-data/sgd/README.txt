Actual full official SGD TRAIN collection and minibatch packet.

Collection: python research/customer-benchmark/day2-training-data/sgd/collect.py
Offline source verification: append --offline.
Process full corpus and locally verify all shard hashes/input/mask/split invariants:
  python research/customer-benchmark/day2-training-data/sgd/process.py
Streaming TRAIN batch smoke read (no model fit):
  python research/customer-benchmark/day2-training-data/sgd/batches.py --manifest research/customer-benchmark/day2-training-data/sgd/full-v1/manifest.json --batch-size 128 --max-batches 2

The source inventory pins the actual official revision and every TRAIN file's publisher blob ancestry; sources.json adds exact SHA256 and byte counts. Official dev/test are never collected. Full source size439,402,926bytes is publisher-inventory evidence for the necessity of crossing400MB to satisfy full TRAIN. Hard collection ceiling450MB, four download workers,15second socket timeout,90seconds/file,600seconds total. Cache is ignored under .cache/. Only downloaded primary JSON is parsed; no publisher code is executed.

Two file-streaming passes freeze all dialogue roots and duplicate normalized observed-input-window/whole-dialogue template closure BEFORE deterministic internal TRAIN/CAL/EVAL allocation. No labels, gold state, service IDs or outcome metrics inform splitting. All components are embargo units, not proven IID; component counts and largest component are reported. Duplicate rows within a component may remain for conversation chronology and ambiguous publisher supervision; they cannot cross splits. Partial previews share ancestry with full data and are not fit-ready while full closure is pending.

Every example is a USER turn. row.input contains only the sanitized current utterance, observed USER speaker and at most8 observed earlier USER/SYSTEM turns. No current frames, actions, state, spans, service calls/results, dialogue IDs, target values or source service labels enter input. Gold slot spans do not drive input redaction. No prior gold state is a runtime feature. Only observed turn order and speakers may create graph edges. A separate all26-service schema branch is allowed under the declared protocol; do not select schema membership from the current gold frame. Source is_transactional metadata is never actual bank authority.

Targets preserve publisher frame service and active_intent (including actual NONE), requested_slots, state-map slot presence, actions and masked values, namespaced by service schema. Missing state/field/frame is unknown and cannot become a negative or DELETE. Presence is membership in the publisher's reported state dictionary, not real-world truth. Only consecutive USER frames of the same service provide KEEP/SET map deltas; update loss masks require value identity recoverability from sanitized observed inputs. DELETE remains masked because no independent annotation completeness certificate was established. Actual source AFFIRM/CONFIRM-related semantics do not establish financial consent, permission or receipts. No bank policy/ledger gold is supplied.

Values are text/null plus value_recoverability_mask and source-value hash. A value target is recoverable only when unchanged by text-only privacy scrubbing and directly visible in the sanitized observed window. Otherwise it is unknown, not a synthetic placeholder target or negative. This conservative criterion excludes canonical normalization and hidden old values. It is not a raw value extraction benchmark.

The text-only privacy scrubber removes contacts, all digit spans, explicit identity/secret spans and possible capitalized names. It deliberately loses some semantic content and is heuristic, not a guarantee against all indirect identifiers. Source hashes and bookkeeping are never features. Raw corpus is not sent to any hosted agent. Processed large shards are ignored local-runs/customer-benchmark-day2-sgd/ and each shard is at most19,500,000bytes (<20MB). Shard paths, actual rows, exact SHA256, source ancestry, target/mask counts and group closure are pinned in each ready manifest.

batches.iter_batches builds an ignored SQLite byte-offset index after checking every requested-split shard SHA256/size/count. It shuffles closure groups and conversations deterministically by seed, keeps USER turn order inside conversations, and yields at most512 rows/batch (default128). Sampling metadata supplies group row count and equal-group loss weight outside input. Caller must detach typed/predicted state between conversations and must not share state/caches across splits. TRAIN is default; CAL/EVAL require an explicit heldout-read flag and must never fit weights. No model is imported, trained or evaluated by these scripts.
