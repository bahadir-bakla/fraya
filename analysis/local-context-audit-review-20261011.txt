P1 PKG-01 — Invalid audit/provenance accepted during packaging
competition/package_submission.py:60,71,74
The packager recursively archives run files and hashes their current bytes without validating request/FULL/audit or comparing recorded builder evidence hashes. A disposable synthetic completed/published run with an export was accepted even with audit source indices 999/999, bank_authority=true, financial_authorization=APPROVED, empty FULL/request objects and a conflicting zero trace hash. The archive's fresh hash matched the invalid audit. This is a submission provenance blocker; validate_audit itself would reject the artifact. Cicero should validate companions against archived sources and recorded hashes before collecting bytes, handle path relocation without changing original request provenance, and preserve explicit classic/unavailable behavior.

P2 PKG-02 — Windows manifest paths do not match ZIP names
competition/package_submission.py:53,60,70,76
str(relative_to(...)) produces backslashes in nested manifest paths; ZIP entries normalize them to forward slashes. Reproduction produced manifest path competition/runs/synthetic/work\finetuned-context-evidence.json and ZIP path competition/runs/synthetic/work/finetuned-context-evidence.json. Two manifest entries were absent verbatim from the fixture archive. Cicero should use .as_posix() consistently and verify each manifest path/digest against the exact archive entry. This is a pre-existing generic packaging issue affecting audit reviewability.
