Method and limits
  Tests construct the actual builder_live.LiveBackend and use production call,
  deploy, practice, Evidence, and (for model/hook gates and overall status)
  build_live. The stateful mock replaces only freya_mcp.bridge.Config/Bridge.
  A deterministic clock advances polling without real sleeps. Actual HTTPX
  send methods are guarded to raise on accidental network requests. The root
  is an empty temporary path, so the credential launcher cannot be loaded.
  Provider responses, customer IDs, variables, transcripts and verdicts are
  synthetic. Real input inventory, policy/coverage validation and workflow lint
  run for build-level cases; minimal synthetic local kit references feed prompts.
  No compiler/model process runs. Mock artifacts stay in unique system temp dirs;
  pytest cache and bytecode writes are disabled.

  This verifies backend behavior against documented Bridge return shapes. It
  does not verify hosted schema acceptance, model quality, actual remote timing,
  Bridge internal compound-request budgets, or atomic workspace locking. The
  mock rejects overlapping starts; Bridge's own concurrent-start race handling
  is outside this isolated test file. Final-ready remains false in build results.
