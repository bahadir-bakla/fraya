HIGHEST CONCRETE FINDINGS

F01 [P1] Builder validates the name's schema without binding it to URL/method.
competition/validation.py:49-61 accepts any allowlisted bank URL, then chooses
'/'+function.name before considering the URL. The method is never checked.
Reproducer: logical verify_identity; correct identity body properties/required;
url default https://freya-bank-mock.freyavoice.workers.dev/v1/create_promise;
method default DELETE; maxRetries=0. Put it in a conversation node with a valid
initial_node and nonempty TTS entry. Observed validate(workflow, api) == [].
POST against that wrong endpoint also passes local validation. Freya dry-run or
real bank execution might reject it; this is a local false acceptance.
Patch: resolve rendered URL + method to one supplied operation, require logical
identity consistency, resolve request-schema references, validate fixed defaults.

F02 [P1] The new kernel replay masks the same binding error.
integrations/customer-datasets/workflow_replay.py:294-299 resolves only body and
calls Bank.call(function['name'], body), ignoring URL/method and final transport
binding. Reproducer: an in-memory five-action graph from EDGE-full_payment-00's
canonical DOB, phone, account, promise, close calls. Preserve body schemas and
defaults; set EVERY API URL to /v1/create_promise and EVERY method to DELETE.
Silent API nodes route with always to an end_call node. Replay(...).run([])
returned kernel_ledger_pass=True, error=None. No generated export/model ran.
The zero-actor toy control establishes a dispatch blind spot; replay correctly
disclaims voice/judge coverage. Patch: validate URL/method before Bank dispatch
or explicitly reject unsupported transport semantics. See RT-16.

F03 [P1] B note-only traces bypass identity and returned account provenance.
benchmark_adapter.py:246-264 checks supplied-product provenance for promises
only. research/field-cases/local_runner.py:170-175 gates account/promise, while
notes need only match ids privately known by the oracle; Bank:122-123 accepts
notes without verification/account access. This is a local simulator loophole,
not evidence that the hosted bank authorizes such actions.
Reproducer: load DATA-024 and replay reference_tool_calls[3:] — three paid notes
and close, with both verification calls and get_account removed. score(case,
ledger) returned ledger_and_trace_pass=True. Overall pass=False solely because
conversation was not assessed. A mistaken passing transcript verdict removes
that last gate. Second reproducer: EDGE-mixed_products-00, truncate the successful
get_account result.products to its first/card record. Notes on absent p2/p3 still
pass ledger/trace checks. Patch: notes also need verification, successful account
provenance, a complete ordered product receipt, and actual product disposition.
Keep all notes pending until the eventual transfer decision. RT-01/02/10/12.

F04 [P1] Explicitly contradictory verification receipts remain accepted.

and validate counters when present. Missing optional API fields alone are not a
proven API-contract violation. RT-05/07.
