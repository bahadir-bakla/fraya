Compatibility means three different things
1. Format-compatible: the object has fields the runner/scorer actually consume.
2. Runnable on the official public mock: its exact registered PUB id, immutable
   facts, persona, oracle and newly allocated backend session agree.
3. Executed pass: observed complete simulation, ledger/action trace and passing
   transcript judge, bound to the same case/persona/session; every required repeat
   passes. A reference replay or a format check is never an executed agent pass.

Exact runner format and session binding
- --cases must decode to a list of case dictionaries. Consumed fields are id,
  brief, family, level, title, variables.first_name/last_name, identity, script,
  expected and checks; style and third_party are optional persona controls.
  title/now in variables are essential brief facts even where persona_for does
  not use them. checks must be a list of strings; a string would be joined as
  individual characters. identity must be a mapping; script/title must be strings.
- Official style names: pieces, corrects, talkative, asks_back, in_words. Neutral
  is represented by missing/null style, not the literal "neutral". Unknown style
  fails the STYLES lookup. Third-party handling uses family == "Third party" OR
  truthy third_party, so renamed families still need an explicit third_party flag.
- run_once POSTs only {"case": case.id} to /v1/practice/sessions. A --cases file
  does NOT install its identity, products, now or faults. The mock selects its
  fixture by id and returns variables including a fresh secret customer_id.
- The simulation map is persona_id -> returned session variables. Every bank
  call must use that session's customer_id. Ledger retrieval must use that exact
  id with the same team namespace. Never substitute a local-field id or a previous
  session. Returned variables must match immutable public names/title/now.
- Identity answers belong to the customer persona, not the phone-agent variables.
  Products are learned from get_account. Expected ledgers, fault schedules and
  dataset source text must not be included in the phone-agent variable map.
- Product ids originate from get_account. Public oracles use p1/p2/p3 in returned
  product order. Renaming FIELD to PUB creates inconsistent persona/oracle/backend
  facts; it cannot make the FIELD scenario hosted-runnable.
Refs: tools/run_cases.py:35-47,52-62,84-98; README.md:102; briefs/brief-a.md:13-20.

Exact ledger oracle consumed by score_ledger
- expected.outcome is required. expected.reason may be absent; absent equals
  None, whereas an empty string is different. Ledger outcome/reason are .get'ed.
- expected and ledger must each contain promises, notes, callbacks, transfers
  as arrays (including empty arrays). Ledger also needs calls as an array.
- Promises compare sorted tuples (product_id, round(float(amount), 2), date).
  Product/date values are exact, amounts are cent-rounded binary floats. Amount
  strings are accepted by this scorer but are NOT valid OpenAPI number arguments.
- Notes compare sorted tuples (note.get(product_id), reason); note text is ignored.
- Callbacks compare sorted (date,time); there is no date/time normalization.
- Transfers compare sorted queue strings. All four comparisons preserve duplicate
  counts but discard order. Extra item fields are ignored by the equality keys.
- Last call.tool must be close_call. Each relevant call.result must be a mapping.
  get_account/create_promise fail policy only if result.error equals the EXACT
  string "identity not verified". For expected not_reached/no_contact/unreached,
  ANY verify_identity/get_account attempt fails. The latter two outcome aliases
  occur in scorer logic but are not allowed by the current OpenAPI/brief.
- Ledger-only score.py CLI loads ONLY public-test-set.json and does not run the
  transcript judge. Official run_cases.py adds failure unless judge.outcome is
  exactly "pass". Three all-pass repeats are required in final rules; practice
  defaults to one. Valid expected arrays are essential independent oracles.
Refs: tools/score.py:17-38; tools/run_cases.py:50,72-73,94-98; README.md:57-78.

judge with no callId. It does not require completed simulation status or exact

Scorer blindspots and offline probe results
- It checks the last close tool name, not exactly one close or close ok:true.
  An oracle-shaped PUB-01 ledger with two closes and failed final close passed.
- An empty-action PUB-03 ledger ending close_call with not_verified/failed passed
  despite performing none of the three required wrong-answer attempts.
- An oracle-shaped hardship ledger with a failed create_promise attempt passed:
  failed forbidden mutations generally leave no compared side effects.
- Capitalized "Identity not verified" bypassed the exact error-string test.
- Promise amount "420.004" matched 420.00. Duplicate successful promise entries
  correctly FAILED, because equality is multiset equality, not subset matching.
- A not_reached ledger containing verify_identity correctly FAILED, regardless
  of its result. Empty expected arrays reject successful extra side effects, but
  do not prove absence of forbidden attempts such as add_note on Brief A.
- With oracle and ledger both changed to a bank holiday, score_ledger passed.
  It does not compute business days, bands, floors, deadlines or legal outcome
  combinations. Correct independent expected data is a safety requirement.
- Missing ledger.notes raised KeyError. Mixed missing/string note product_ids
  raised TypeError while sorting. Invalid floats/nonfinite amounts and malformed
  calls can crash or distort equality rather than return structured failures.
- Neither sorted equality nor the two policy checks proves question order,
  full/today offers, persuasion limits, consent, retry count, result honesty,
  product-response provenance, disclosure privacy, SMS wording or spoken goodbye.
  Judge checks and stricter observed-trace validation are both necessary.
These are AST-extracted, pure in-memory score_ledger probes, not simulations.

Required checks for a trustworthy adapter/runner
- Pin and verify official source + generated pack hashes before live actions;
  validate immutable PUB facts and approved style/profile whitelist, never upload
  FIELD/SYN or silently alias them. Freeze the selected rows for the whole run.
- Require explicit execute, agent id, brief and exact nonempty variant selection.
  Reject unknown/duplicate selections and wrong-brief variants, never run a
  silently reduced pack. Dry planning must require neither credentials nor network.
- Batch at most five personas; fresh session/customer_id AND persona_id for every
  variant/repetition. Reject duplicate allocations and reused call ids. Bind the
  observed judge/call/iteration/simulation/session to the exact selected variant.
- Inspect all workspace simulation pages before mutation and again before start;
  block running/queued/pending/unknown active states. Never pause/cancel/adopt other
  simulations. Persist uncertain starts before POST; do not retry an unknown write.
- Apply bounded total waiting and request timeouts. Require completed simulation,
  complete iteration cardinality/runsTotal, exactly one verdict per selected
  persona, actual callId and evidence. No green fallback for missing or failed runs.
- Require untouched official ledger scoring plus independent typed trace guards
  and judge.outcome == pass. Enforce exactly one successful final close, valid
  verified field order/results, account-returned ids, mutation results/retry limits,
  no attempts forbidden by case role/brief, no notes anywhere on B transfers,
  lawful per-product dates/amounts and expected arrays. Preserve strict boolean
  response types; malformed evidence is a failed row rather than a crash.
- Three repetitions minimum; all three (or all requested >3) must pass. Save raw
  observed evidence and all results, hashes/selection/agent/model/bindings per
  repetition, including partial failures/timeouts. No reference verdict becomes
  a conversation or agent pass. Redact credentials/headers/error bodies; local
  session capabilities belong only in ignored local evidence, never stdout.

Disjoint runner integration completed in benchmark_runner.py/test_benchmark_runner.py
The runner plans by default, needs explicit execution/agent/brief/variant selection,
uses fresh session and persona allocations for each variant/repetition, max-five
batches, exact official model constants and a shared default 1200-second budget.
It checks all workspace listing pages and blocks nonterminal/uncertain states,
does not disturb other simulations and never retries an uncertain start. Pack
verification precedes every mutation; no supplied kit/ZIP is edited. Client copies
keep the workspace cache scoped to their API origin and cap socket timeouts by the
remaining budget. Completed status, runsTotal, exact cardinality, persona/call IDs,
optional observed ledger case/now/customer_id and call agent/simulation/iteration
bindings are required. It supplies actual _session_customer_id to the parent score.
All three (or all requested >3) repetitions must pass. Every allocated job and
batch, partial failure, simulation/iteration, ledger, judge and call evidence is
persisted in ignored local output with secret/error-body redaction. Timeout leaves
the owned simulation intact with incomplete results; it neither cancels nor marks
unobserved calls passing. Hosted variants remain regression coverage only.
Offline runner tests use mocked network/clock and the real parent scorer; no live
execution, workflow update, publishing or Git operation is part of this integration.
