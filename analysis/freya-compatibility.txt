B02 [blocker] Condition syntax and collection gates change behavior
The emitter uses gt/lt/gte/lte and value; Freya documents greater_than/less_than and operand. Variable checks should be in a top-level OR, with AND nested inside it. slots_filled is emitted without any condition. confirmed/rejected pass the spec grammar but runtime._holds never implements them. Boolean equality is unsafe because Freya compares string representations.
Adapter: Compile slots_filled to an AND of is_set checks inside OR; translate operators, use explicit string status flags, and implement or reject confirmed/rejected. For integer attempts>=N use greater_than N-1; for general numeric >=/<= use normalized code predicates or a tested compound condition.

Concrete adapter requirements
A01 Dedicated official workflow emitter and validator (B01, B02)
Bare workflow has initial_node pointing to a node-map key, official node fields, per-node transitions, no legacy edges/variables/type/data transport fields, and a reachable terminal on every realistic branch.
A02 OpenAPI-backed tool binding registry (B03, B04)
Every referenced semantic action resolves to exact HTTP parameters/schema and business success predicate; baked defaults and model-filled body fields are explicit; missing bindings fail the build.
A03 Prompt, extraction and variable adapter (B05)
Explicit extraction types/confidence; safe double-brace prompt substitution; ISO date conversion; per-call inputs supplied; derived values initialized; stale results reset on repeat actions. Do not rely on context_variables: the kit reports it being silently dropped (workflow-format.md:244-246).
A04 Executable guards for writes and joins (B02, B06, B12)
Separate read-back/confirmation/correction states; constraints and aggregate join success block entry to write actions; explicit string status flags; any generated code_exec reads vars, catches errors and sets fallback outputs, with no double-brace delimiters (tools-and-code.md:492-499).
A05 Freya routing and retry semantics (B07, B08)
Explicit interrupt priority, variable-based collection gates, business versus transport retry counts, bounded unanswered turns, reset policy and passthrough fallbacks. Preserve the brief's policy rather than copying mock counters.
A06 Terminal and lifecycle binding (B09)
Transfer and bank close operations execute with valid enums/inputs; close runs once and last; terminal farewell comes from end_call.function parameters; no unconfirmed native telephony assumptions.
A07 Specialist graph flattening (B11)
Stable snake_case node keys and variable ownership; carried state is assigned explicitly; static return branches or appropriate __previous__ global returns; no undocumented dynamic targetVariable/parallel metadata.
A08 Artifact/request normalization and lifecycle client (B01, B10)
Internal spec, bare workflow, create/update request and exported metadata wrapper remain distinct. Optional nulls removed using a write allowlist. Future deployment uses stable slots, dry-run, publish, read-back and ID persistence.
A09 Simulation request adapter (B10, B12)
Real persona and agent IDs, customerVariablesMap, chat mode for kit practice, all event model overrides, duration/concurrency controls, configurable k and trace-based checks. Guarded offline pass and platform pass are reported separately.
